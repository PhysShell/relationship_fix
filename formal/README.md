# formal/ — semantic kernel, не весь pipeline

Маленькая формальная модель наблюдения: огрубление часов, допустимые
линеаризации, возможности, идентифицированное множество `N`.

```
TrustedSpec/     определения И формулировки — ВОПРОС. Меняется редко
Proofs/          доказательства — ОТВЕТ. Меняются часто
Verification/    Challenge (:= sorry), Solution, судья, FinalCheck
```

Граница между первым и вторым — не стиль. Главная угроза здесь уже не
`sorry` (его ноль), а доказать безупречную теорему о незаметно изменённой
модели. `Challenge.lean` импортирует только `TrustedSpec`, хэши вопроса
попадают в сертификат, а судья проверяет, что solution доказывает именно
замороженную формулировку.

```
./scripts/audit.sh    все слои + сертификат
lake build            только сборка
```

Lean 4.34.0, **без Mathlib**: нужен только `List.Perm` из core. Ядро обязано
собираться из одного тулчейна, чтобы «доказано» не опиралось на гигабайты
чужого кода и на доступ к сети.

Статус КАЖДОГО утверждения — `docs/formal-model.md`. Там же честно написано,
чего здесь нет: upstream `comparator` и второй независимый kernel.
