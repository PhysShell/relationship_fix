# `TiePolicy.BOUNDED`: точная partial identification для двухакторных потоков

**Статус:** движок построен и проверен тремя способами. Прогон по корпусу —
ниже.
**Код:** `coarsening/bounded.py`, тесты `tests/test_bounded.py`, прогон
`tools/bounded_q1c.py`.

## 1. Почему это перестало быть украшением

Измерение первого этажа показало не «63% ties, неприятно», а более
неприятную вещь: **STRICT на минутной шкале меняет эстиманд.**

Пусть `A` = возможность задета неоднозначной группой меток, `I = 1 − A`,
`T` = латентность возврата. Мы хотели оценивать

```
E[min(T, H) | eligible]
```

а STRICT фактически даёт

```
E[min(T, H) | eligible, I = 1]
```

и секундная рука показывает, что `I` и `T` зависимы жёстко: исключённые
возможности имеют медиану **1 минуту**, оставшиеся — **6**. Это не безобидная
missingness, это отбор по самой величине, которую мы измеряем.

Для будущего эксперимента с вмешательством — хуже. Если prompting двигает
латентность или плотность сообщений, он двигает и вероятность попасть в
неоднозначную группу:

```
Z  →  messaging behaviour / density  →  ambiguity  →  STRICT inclusion
```

то есть **включение в анализ становится пост-тритмент переменной**, и
рандомизация анализ уже не спасает, если мы обусловливаемся на `I = 1`. Это
родственник найденной раньше проблемы с treatment-dependent `N`, только
пришедший через measurement process, а не через поведение.

Строчка в `TiePolicy.BOUNDED` — *«should be paid for by a measured rate of
ambiguity, not by the theoretical existence of ties»* — оплачена.

## 2. Почему НЕ generic partial-order engine

Process-mining литература рассматривает ровно эту ситуацию: при coarse или
совпадающих метках total order не наблюдается, и рекомендуется хранить
множество совместимых порядков, а не придумывать вторичный. Там же есть
предупреждение почти дословно про наш случай: инструмент, произвольно
упорядочивающий события с одинаковыми метками, **создаёт искусственные
process variants** — что мы и увидели, когда огрубление УВЕЛИЧИЛО число серий
в 84 диадах из 517.

Но общие методы упираются в перебор linear extensions и факториальную
сложность. У нас задача проще благодаря двум свойствам:

```
диада            = ровно два актёра
минутные корзины = порядок МЕЖДУ корзинами известен
                   порядок ВНУТРИ корзины неизвестен
```

Это позволяет точный специализированный DP. Поэтому: **нет** probabilistic
ordering, **нет** learned tie model, **нет** generic DAG framework.

## 3. Корзина — это не последовательность

Минутная корзина больше не `A A B A B`, а

```
minute 12:34
  A × 3
  B × 2
```

и допустимы все расстановки, совместимые с кратностями. При этом перестановки
одного и того же актёра нам безразличны — существенен только **сжатый шаблон
чередования**:

```
AAABB → A B
ABABA → A B A B A
BAAAB → B A B
```

Поэтому вариантов `O(min(a, b))`, а не `C(a+b, a)`. Шаблон параметризуется
как `(кто первый, блоков P, блоков Q)` с `|p − q| ≤ 1`.

DP переносит между корзинами состояние

```
open_since ∈ {None} ∪ {начало корзины, где открыта серия}
```

и при закрытии возможности добавляет `N += 1`, `B += min(latency, H)`.
Состояний мало: любая корзина с участником закрывает открытую серию, поэтому
множество достижимых состояний не растёт.

## 4. Ловушка, из-за которой границы считаются на ЦЕЛОМ порядке

**Нельзя** найти минимальную латентность каждой возможности отдельно, сложить
минимумы и назвать это нижней границей. Минимум возможности №1 и минимум
возможности №2 могут требовать взаимоисключающих порядков одной и той же
корзины.

Ровно поэтому DP оптимизирует аддитивную величину по одному целостному
допустимому порядку, а не по возможностям по отдельности.

Тот же эффект есть и во временном слое, и он учтён точно: **спаны
возможностей, закрывшихся внутри одной корзины, не пересекаются**, поэтому
сумма их латентностей не больше ширины корзины. Верхний вклад группы из `c`
таких возможностей равен `min(Δ, c·H)`, а не `c·min(Δ, H)` — второе не
достигается ни при каком порядке.

## 4a. Терминология: что резкое, а что оболочка

Слой порядка считается точно, слой времени — валидной внешней оболочкой.
Поэтому про две величины говорится по-разному, и это не педантизм, а способ
не дать рецензенту дешёвую зацепку.

```
N      sharp identified set
       точное множество значений, совместимых с наблюдёнными метками

RMTR   valid outer identification envelope
       заведомо не уже истинного множества
```

Из этого следует **усиление**, а не ослабление:

```
STRICT ∉ outer envelope
   ⟹  STRICT ∉ неизвестного sharp set, лежащего ВНУТРИ оболочки
```

То есть «не совпал с каким-то возможным порядком» — слабая формулировка.
Верная: оценка лежит снаружи **заведомо слишком широкой** оболочки. Ослабляет
это только обратное утверждение: «точка внутри оболочки» само по себе ничего
не доказывает.

По той же причине ширина называется **width of the valid envelope**, а не
«точность идентификации до фактора 4.7»: вторая фраза обещала бы резкость,
которой движок пока не даёт.

## 4b. Что именно теперь доказано

Раньше цепочка была эмпирической:

```
ambiguity → STRICT exclusion → исключённые быстрее → RMTR уезжает вверх
```

Теперь она структурная:

```
грубое наблюдение
  → множество допустимых latent histories
  → каждая даёт значение целевого функционала
  → BOUNDED охватывает все такие значения
STRICT ∉ этого множества
```

Значит STRICT здесь **не** является шумной или неэффективной оценкой той же
величины. Он считает **другой функционал**:

```
цель     метрика по ВСЕМ возможностям под какой-нибудь хронологией,
         совместимой с наблюдением
STRICT   метрика по возможностям, ПЕРЕЖИВШИМ правило исключения,
         которое само зависит от неоднозначности
```

И выживание зависит от поведения: быстрое плотное взаимодействие даёт больше
межакторных столкновений, значит больше исключений. Для будущего эксперимента
это остаётся механизмом пост-тритмент отбора.

## 5. Отношение `R = B / N` — отдельная осторожность

**Нельзя** писать

```
R_min = B_min / N_max
R_max = B_max / N_min
```

и звать это границами: `B_min` и `N_max` достигаются, вообще говоря, на
разных допустимых порядках. Это в лучшем случае нерезкая оболочка.

Правильно — дробная оптимизация: искать `λ`, при котором экстремум `B − λN`
обращается в ноль. Тогда `λ` и есть экстремум отношения, достигаемый одним
целостным порядком. `B` и `N` складываются по переходам DP, значит и `B − λN`
складывается, так что это тот же самый DP с изменёнными весами. Хранить весь
зоопарк достижимых пар `(N, B)` не нужно.

## 6. Два слоя неопределённости, разделённые намеренно

```
ORDER  какие серии и возможности вообще возможны
TIME   какие латентности возможны при каждой допустимой топологии
```

Второй слой — обычное interval censoring: метка `12:34` означает
`[12:34:00, 12:35:00)`, и подстановка одной точки интервала даёт смещение.
Границы:

```
ответ в той же корзине     T ∈ [0, Δ]
ответ в корзине через d    T ∈ [d − Δ, d + Δ]
возврата не было           вносит ровно H
```

Для `H = 6 ч / 24 ч` эта ±минута почти декоративна. Для `H = 1 мин` — нет, и
поэтому `+0.29 мин` при `H = 1 мин` нельзя читать так же расслабленно, как
`+36 мин` при `H = 24 ч`. Слои считаются отдельно (`time_layer=False` даёт
чистый слой порядка), и оба сообщаются.

## 7. Три проверки, и ни одна не верит DP на слово

**Переборный оракул.** На микротрассах (1–4 корзины, малые кратности)
перечисляются ВСЕ расстановки актёров, и экстремумы сравниваются с DP.
Оракул независим: он не знает ни про сжатые шаблоны, ни про состояния.
240 случайных трасс, оба слоя.

**Монотонность по измельчению.**

```
identified_set(1 с)  ⊆  identified_set(60 с)
```

потому что минутное огрубление только удаляет информацию. Эта проверка лучше
сравнения с «истинной» секундной последовательностью именно потому, что 1 с у
нас **тоже не истина**: там остаются свои 1.9% неоднозначных возможностей.

**Схлопывание.** Где хронология однозначна (ни одной смешанной корзины),
`low == high ==` результат обычного экстрактора. BOUNDED обязан деградировать
в существующий движок, а не стать вторым определением метрики.

## 8. Почему тихие random tie-breaks ничего не спасали

Разброс 0.58 pp по восьми розыгрышам можно было бы прочесть как «перестановки
почти одинаковы, значит случайный tie-break достаточно хорош». Нет. Стабильно
лишь **сколько выкинуто**, а не какие возможности существуют и какая
латентность какой из них принадлежит.

Вдобавок равномерный случайный порядок внутри корзины вводит вероятностную
модель, которой источник не давал. Почему `ABBA` должно быть столь же
вероятно, как `AABB`? Не на чем.

Partial identification честнее: источник разрешает множество порядков →
результат ∈ `[L, U]`. А не: мы бросили виртуальную монетку и получили
4.37 минуты.

## 9. Интерфейс с гейтом решения

```
весь интервал вне [−δ, +δ]     → REACTIVITY_SIGNAL      identified
весь интервал внутри [−δ, +δ]  → PRACTICALLY_NEGLIGIBLE  identified
иначе                          → ORDER_AMBIGUOUS
эстиманда нет                  → UNDEFINED
```

`ORDER_AMBIGUOUS` — **не** то же, что статистический `INCONCLUSIVE`, и имя у
него своё. Это неидентифицированность: увеличением `N` не лечится, потому что
источник просто не различает нужные порядки.

Если минутные данные дают `[−4 мин, +37 мин]`, правильный результат не
«поищем модель поумнее, которая выдаст +12.3 ± 4.1», а

> minute-resolution source недостаточно идентифицирует нужный causal endpoint.

И тогда всё: источник не годится для этой задачи.

## 10. Поправка к плану по генератору

Таблица `P(ambiguous | occupancy)` **не** едет в генератор как параметр
Бернулли. Это был бы новый маленький `tie_rate`, только в хорошем костюме.

Механизм уже есть и он лучше:

```
генератор → высокоразрешённый поток → НАСТОЯЩИЙ оператор C_60
          → неоднозначность выводится настоящей TiePolicy
```

Причина видна прямо из чисел: при `occupancy = 1` вероятность всё равно
**0.228**, потому что возможность касается соседних корзин — конца серии и
ответа. Значит занятость одной корзины **не является достаточным состоянием
процесса**, и Бернулли по ней порождал бы неоднозначности, независимые от
структуры, которая их на самом деле порождает.

Роль таблицы — **calibration target и диагностика**. Воспроизводит генератор
эту кривую после настоящего `C_60` — хорошо. Не воспроизводит — это
рассогласование локальной структуры генератора, а не повод подкрутить `p`.
Записано константой `USE_AS_GENERATIVE_BERNOULLI = "FORBIDDEN"` и тестом.


## 11. Сертификат измельчения: что теорема, а что диагностика

Формулировка, разделяющая математику движка и консервативность слоя
аппроксимации:

> Refinement monotonicity is a theorem for the sharp order layer and an
> empirical diagnostic, not a theorem, for the conservative temporal outer
> envelope.

Разложение по величинам:

```
N                  HARD INVARIANT — теорема; нарушение = БАГ
R outer envelope   DIAGNOSTIC — нарушение багом само по себе не является
R order-only       NOT COMPARABLE ACROSS RESOLUTIONS
```

**`N` — теорема, и секунды тут ни при чём.** `N` зависит только от допустимой
топологии порядка актёров; временной бюджет `min(Δ, c·H)` в неё не входит
вообще. Огрубление 1 с → 60 с лишь **стирает** ограничения порядка, поэтому
любая хронология, допустимая при 1 с, допустима и при 60 с. Если вложение по
`N` сломается — это баг в огрублении, сборке корзин, состоянии возможности
или DP, и списывать его на правило вклада нельзя. Прежняя моя формулировка
(«если вложение сломается, это находка про моё правило вклада») была слишком
широкой и годилась бы как готовое оправдание для настоящего бага.

**Оболочка — диагностика.** `outer_R(1 с)` сама содержит значения, физически
недостижимые. `outer_R(60 с)` обязана содержать **резкое** множество при
60 с, а не все ложноположительные точки мелкой аппроксимации. Её вложение
наблюдается, но теоремой не является.

### Поправка, найденная тестом, а не рассуждением

Третий пункт классификации пришлось изменить: слой порядка **не** является
hard invariant при сравнении разрешений.

При `time_layer=False` латентность равна разности **начал корзин** — та самая
подстановка одной точки интервала, про которую предупреждает coarse-data
литература. Она зависит от разрешения: при 60 с латентность обязана быть
кратна 60, поэтому значение 103 с там просто не существует.

Воспроизводимый контрпример (18 сообщений, `H = 5 мин`):

```
order-only   1 с   [103, 131]
order-only  60 с   [120, 600]      103 НЕ внутри
envelope     1 с   [ 99, 136]
envelope    60 с   [  0, 960]      вложено
N            1 с   [  4,   5]
N           60 с   [  3,   7]      вложено
```

Два слоя порядка на разных разрешениях — не одно множество, посчитанное
точнее, а **две разные величины**. Внутри одного разрешения слой порядка
остаётся тем, ради чего заведён: инструментом разложения ширины на порядок и
время. Между разрешениями он не сравнивается, и сертификат его не проверяет.

## B1. Оценка STRICT лежит вне допустимого множества — почти всегда

```
                                            H=5 мин   H=60 мин   H=24 ч
STRICT N вне SHARP-множества                 98.1%     98.1%      98.1%
STRICT RMTR вне ВНЕШНЕЙ ОБОЛОЧКИ             36.9%     87.6%      77.7%
```

**Направление однозначно и проверено отдельно:**

```
N     ниже нижней границы   513 диад      выше верхней   0
RMTR  выше верхней границы  190/451/398   ниже нижней    0/0/2
```

STRICT систематически **недосчитывает возможности** и систематически
**завышает RMTR** — ровно то, что предсказывала селекция по латентности.

Величина промаха:

```
N     p25=222   p50=828   p75=2109   p95=6362  возможностей
      в ширинах оболочки: p50 = 0.69

RMTR  H=60 мин   p50 = 3.09 мин   p95 = 9.31 мин
      H=24 ч     p50 = 14.25 мин  p95 = 77.76 мин
```

Формулировка, которую разрешает такой результат, звучит сильнее наивной. Не
«STRICT не совпал с каким-то возможным порядком», а:

> STRICT RMTR лежит вне **валидной внешней оболочки**; следовательно, он тем
> более не принадлежит неизвестному резкому множеству внутри неё.

Для `N` слой порядка точен, поэтому там формулировка прямая: **STRICT N вне
sharp identified set**, совместимого с наблюдёнными минутными метками.

*Поправка единиц.* Порог `VIOLATION_FLOOR_SECONDS = 1.0` применялся и к `N`,
которое измеряется в возможностях. Численно безвредно (промах в одну
возможность и правда маргинален), но названо было неверно: сырых нарушений
513, с порогом — 507. Заведена отдельная константа `VIOLATION_FLOOR_COUNT`.

## B2. Границы информативны

```
N     относительная ширина          p25=0.34  p50=0.53  p75=0.70
RMTR  мультипликативная ширина      H=5 мин  x3.00
                                    H=60 мин x2.28
```

Там, где STRICT выдаёт **неправильное число**, BOUNDED выдаёт **правильное
множество** шириной примерно вдвое. Это не «минутные данные бесполезны», а
«минутные данные ограничивают величину с точностью до фактора два, и вот с
какой».

## B5. Связь с локальной плотностью — то, что завершает Q1c

```
H = 60 мин          диапазон плотности   STRICT снаружи   ширина оболочки
  Q1   1.03 .. 1.62                          69.8%            x1.44
  Q2   1.63 .. 1.92                          87.6%            x2.04
  Q3   1.92 .. 2.40                          94.6%            x2.70
  Q4   2.40 .. 9.51                          96.9%            x4.18

H = 5 мин
  Q1                                         15.5%            x1.67
  Q4                                         71.5%            x6.19
```

Вот теперь вопрос Q1c закрыт содержательно. Не «плотность → P(ambiguous)», а:

> при росте локальной плотности огрубление перестаёт просто добавлять
> неоднозначность и начинает **уничтожать точечную идентификацию**: доля
> диад, где точечная оценка вообще несовместима с наблюдениями, идёт от
> 15.5% в нижнем квартиле до 71.5% в верхнем уже на пятиминутном горизонте.
