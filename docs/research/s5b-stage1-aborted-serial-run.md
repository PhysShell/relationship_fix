# S5b Stage 1, первый serial-прогон: ABORTED_INVALID_IMPLEMENTATION

**Статус: аннулирован. Ни один результат не переносится в S5b.**

## Что было запущено

Последовательный прогон этапа 1 на одноядерной VPS, остановлен вручную на
57 руках из 156 (весь `rate = 1.5`, 18 из `rate = 6.0`).

```
executable        /tmp/claude-0/s5b/stage1.py     sha256 a48c59db31f0e15b
output            arms.jsonl, 57 записей          sha256 41516782323b87f6
прогресс          progress.txt                    sha256 b37e4d9c1524f822
сохранено в       runs/s5b-stage1-serial/         (не версионируется, ADR-0003)
```

## Почему аннулирован — две причины, обе дисквалифицирующие

**1. Executable не был под контролем версий.** Прогон шёл из `/tmp`, то
есть из кода, которого нет в истории и который исчезнет вместе с
контейнером. Для `S5a-RATIO` скрипт хотя бы пришпилен дайджестом; здесь не
было и этого. Научный результат, происхождение которого нельзя предъявить,
результатом не является — это прямое требование ADR-0003.

**2. Обязательное prereg-правило MC-точности не было реализовано.** Baseline
`2224eb8` замораживает лестницу `4000 → 16000 → 64000`, цель по MCSE и
статус `MC_PRECISION_INSUFFICIENT`. Запущенный код брал фиксированное
`M = 4000`, **не вычислял стандартную ошибку вообще**, не эскалировал и не
выставлял ни одного статуса точности. Правило точности — часть гейта, а не
довесок к нему, поэтому поверхность без него неполна относительно
собственного prereg.

## Что с этими 57 руками можно и чего нельзя

```
МОЖНО   использовать как EQUIVALENCE ORACLE при M = 4000:
        восстановленный tracked entrypoint обязан воспроизводить их побитово

НЕЛЬЗЯ  переносить в S5b любой научный вывод — PASS, FAIL, AMBIGUOUS,
        оценку доли неоднозначных ячеек, любое утверждение о поверхности

НЕЛЬЗЯ  использовать как checkpoint для M = 16000 / 64000: в записи хранятся
        только арм-уровневые концы λ∓, без period-level достаточных
        статистик. Доопределять недостающее задним числом запрещено
```

## Восстановление

`research/python/simulation/s5b_stage1.py` — tracked entrypoint, семантика не
изменена. Побитовая эквивалентность проверена на стратифицированной выборке
(первая, средняя и последняя рука каждого `rate`): **6 из 6 совпали, максимум
расхождения 0.0 по 72 ключам каждая.**

Модуль намеренно НЕ реализует лестницу и статусы точности — см.
`s5b-mcse-specification-gap.md`.
