# S4-CLOSURE: что изменилось в допустимом дизайне измерения

**Это решение, а не эксперимент.** Ни одного нового числа здесь нет. Есть
запись того, что S4 сделал с правилами, по которым дальше можно измерять.

**Машинная версия:** `research/python/coarsening/s4_closure.py`, тесты —
`tests/test_s4_closure.py`. Проза объясняет, тесты следят, чтобы объяснение
не разошлось с решением.

## 0. Зачем этот документ существует

Через месяц S5b сошлётся на S4 как на «мы наконец откалибровали incidence».
S4 этого **не сделал**, и именно этого он не сделал громче всего. Документ
заведён ради одной этой опасности.

## 1. S4-Q1c = CLOSED

Артефакт результата — `coarsening/q1c_result.py`: дайджесты входа и выхода,
коммит, цифры, поимённый `DO_NOT_REOPEN`. Отчёт —

## 2. `STRICT` на грубых метках — не допустимый primary analysis

Не «шумный». Не «консервативный». Он **считает другой функционал**:

```
цель     метрика по ВСЕМ возможностям под какой-нибудь хронологией,
         совместимой с наблюдением
STRICT   метрика по возможностям, ПЕРЕЖИВШИМ правило исключения,
         которое само зависит от неоднозначности
```

И выживание зависит от поведения: быстрое плотное взаимодействие даёт больше
столкновений, значит больше исключений. Для будущего эксперимента это
механизм **пост-тритмент отбора**: если prompting двигает плотность, он
двигает и вероятность попасть в анализ.

### У двух выводов S4 РАЗНАЯ прочность, и путать их нельзя

Их очень хочется произнести одним предложением. Нельзя.

**По `N` — самая прочная цепочка проекта:**

```
STRICT_N < lo          ЭМПИРИЧЕСКИ: 513 диад из 517, выше верхней границы — ноль
lo ≤ N ∀ admissible    ДОКАЗАНО В LEAN (DPBoundsSound)
⟹ STRICT_N < N         для КАЖДОЙ совместимой хронологии
```

Измерение плюс теорема. Разрешено говорить: **оценка STRICT по `N`
несовместима ни с одной допустимой хронологией**.

**По `RMTR` — на ступень осторожнее:**

```
STRICT_RMTR вне оболочки   ЭМПИРИЧЕСКИ: 87.6% диад при H = 60 мин, всегда сверху
оболочка действительно внешняя   ОРАКУЛ + ОБЪЯВЛЕННЫЕ ДОПУЩЕНИЯ, не доказательство
```

Разрешено говорить: **снаружи заведомо слишком широкой оболочки,
следовательно тем более вне резкого множества внутри неё** — с оговоркой «при
условии, что оболочка действительно внешняя». Эта оговорка не риторическая:
soundness временного слоя в Lean не доказана и лежит в морозилке.

Различие сделано структурным, а не только текстовым: в `s4_closure.py` у
каждого утверждения записана **цепочка статусов**, и слабейшее звено у `N` —
`EMPIRICAL`, у `RMTR` — `ASSUMPTION`.

## 3. `TiePolicy.BOUNDED` — политика измерения для грубых данных

`ORDER_AMBIGUOUS` — **нормальный исход**, а не повод выбрать удобный
tie-break. Равномерный случайный порядок внутри корзины вводит вероятностную
модель, которой источник не давал: неоткуда взять, что `ABBA` столь же
вероятно, как `AABB`.

Напоминание, почему тишина розыгрышей ничего не спасала: разброс 0.58 pp по
восьми засеянным перестановкам показывает устойчивость **агрегатной доли
потери**, а не судьбы конкретной возможности.

## 4. Резкий временной слой — `NOT_WORTH_BUILDING`

По порогу, объявленному до прогона: доля ширины от неопределённости порядка
0.64 / 0.84 / 0.96 по горизонтам против объявленного 0.5. Решение принимается
уже широкой оболочкой; сужение не изменит ни одного вывода.

## 5. Q1a остаётся `DOCUMENTED_LIMITATION`

S4 **не измерил** абсолютный `opportunity_rate_per_day`. Что S4 разрешил
калибровать:

* локальную временную структуру потока;
* слияние серий под оператором `C_60`;
* связь неоднозначности с локальной плотностью;
* ширину идентификации, создаваемую неопределённостью порядка;
* поведение грубого наблюдателя.

Чего **не** разрешил:

* абсолютные opportunities в сутки;
* истинную долю неответов в популяции с полным покрытием;
* incidence бремени на фиксированном окне.

### Предложения, запрещённые в S5b — дословно

```
«S4 откалибровал incidence»
«мы знаем типичную плотность переписки»
«opportunity_rate_per_day взят из данных»
«средняя из WhatsApp и NetHealth»
«STRICT даёт консервативную оценку»
```

Последнее — самое коварное: звучит как осторожность, а означает неверное.

## 6. `N_eligible` на правой границе окна — DEFERRED

Огрубление двигает `start` назад, поэтому грубая рука может признать eligible
то, что мелкая не признала (`t = 119`, `H = 60`, окно до 120: `{0} ⊄ {1}`).
Сейчас это краевой случай. Когда появятся настоящие fixed person-period окна,
он станет **частью эстиманда** — тогда и решать.

## 7. Что это означает для S5b

Статус меняется с `BLOCKED_ON_S4` на **`PARTIALLY_UNBLOCKED`**.

| разблокировано | по-прежнему закрыто |
|---|---|
| оператор огрубления | абсолютная incidence как вход дизайна |
| поведение наблюдателя | единственное число pilot N без оси чувствительности |
| ширина идентификации как функция локальной плотности | |

`opportunity_rate_per_day` остаётся **осью сетки чувствительности**, а не
входным числом. Никакого среднего, добытого плоскогубцами из двух чужих
корпусов и объявленного человеческой природой.

И главное изменение вопроса. После S4 и Lean он звучит уже не «можем ли мы
посчитать метрику» — можем, — а:

> при каких условиях источник данных вообще идентифицирует causal endpoint
> достаточно хорошо, чтобы эксперимент имел смысл?

Качество acquisition стало **параметром дизайна эксперимента**, а не
инженерной подробностью.

## 8. Морозилка — с причинами

```
DPBoundsSharp                вывод сильнее не делает; достижимость — оракул
IdentifiedSetIsContiguous    ни один вывод от непрерывности не зависит
temporal layer в Lean        сначала оценить размер задачи
fractional optimization      оракул покрывает, спешить незачем
upstream comparator          несовместимая инфраструктура; судья на месте
nanoda                       закрывает риск №999 при открытых №1-3
sharper time solver          порог сказал NOT_WORTH_BUILDING
седьмой корпус               stop-rule сработал
```

Причина рядом с каждым пунктом не для красоты: морозилка без причин через
месяц читается как список упущений.
