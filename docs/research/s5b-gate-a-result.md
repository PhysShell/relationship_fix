## Что упало и почему

`s_6 = (C6/C1 − 1)/5 = 0.1153`: шесть клеток обошлись в 3689.8 с ЦП
против 2340.7 с у неделёного, **+57.6%**. Смежные четверти того же
прогона — +11.0%. Модель `T(G) = S + Σ cost(key)`, подогнанная на `1` и
`g=4` этого же прогона, занижает КАЖДУЮ клетку на 23.8–25.8%
(предсказано 461.4 с, измерено 605.1–622.2 с).

Механизм виден в коде науки, `s5b_escalation.accumulate`, без нового
вычисления. Работа группы трёхуровневая:

```
на период на ГРУППУ           generate_dyad, Stream
на период на пару (группа, δ) to_bins + префиксы по всем days
на период на КЛЮЧ             achievable_frontier + hull_of
```

`δ` — первая координата ключа, тот самый «блок». Средний уровень модель не
видит: в ней группа платит `S` один раз, а всё остальное делится по
ключам. Число пар (группа, δ) у вариантов:

```
вариант               групп   пар (группа, δ)
первый прогон g=1       1          4
первый прогон g=2       2          4
первый прогон g=4       4          4
этот прогон   g=1       1          4
этот прогон   g=4       4          4
этот прогон   cells6    6         24
```

**Ни один вариант до cells6 блок `δ` не дробил.** Поэтому все четыре
прежние оценки `s`, отложенная проверка PoC (g=2, 1.8% при допуске 5%) и
`s_4` этого прогона согласованы между собой — и ни одна из них не имела
силы против этого провала. cells6 — первое разбиение, раздающее каждый
блок по всем группам, и первое, где модель проверилась на том, что
делают LPT и факториальная раскладка.

Разложение по трём уровням, ПОСТФАКТУМ и с нулём степеней свободы (три
числа на три неизвестных):

```
G (на группу)         = (C4 − C1)/3        = 85.5 с
B (на пару, среднее)  = (C6 − C1 − 5G)/20  = 46.1 с
```

`G` между разбиениями первого прогона плавал 73.9–89.6 с (в масштабе
этого раннера), так что `B` известен как 45–49 с, и это среднее по
четырём `δ`: `to_bins` при разных `δ` вряд ли стоит одинаково. Это
объяснение, подсказанное кодом, а не проверенная модель: проверить её на
имеющихся данных нечем.

## Зонд cells6: статус по правилу и его сила

По правилу: `max/min = 622.2/605.1 = 1.0283 ≤ 1.05` ->
`NOT_DETECTED_DAYS_UNMEASURED`. Ось `days` не измерена вовсе: каждая
клетка содержит все три `days`.

Оговорка о силе. Порог 1.05 задавался в предположении, что клетка — это
почти целиком работа ключей. Здесь каждая клетка несёт одинаковые
накладные: при любом делении на `G` и `B` они равны
`(C6 − C1)/5 = 270 с`, то есть 44% клетки. Одинаковое слагаемое разбавляет
отношение. На части «только ключи» (по тому же постфактум-разложению)
разброс ≈ 1.051 — чуть выше нижнего порога, в зоне НЕ РЕШЕНО. Статус по правилу остаётся
`NOT_DETECTED_DAYS_UNMEASURED`; вес у него меньше задуманного, и эффект
horizon/maximise до 5% этим зондом не исключён.

Наблюдение, не вывод: обе клетки horizon 300 (605.6 и 605.1 с) дешевле
остальных четырёх (618.4–622.2 с) на 2–3%; `maximise` внутри
горизонта различается не больше чем на 0.6%.
