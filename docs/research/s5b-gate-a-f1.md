# Gate A-F1: трёхуровневая модель стоимости группы ключей

Локальный gate, без Actions. Код — `execution/s5b_execution/threelevel.py`,
к планировщику НЕ подключён (проверяется импортом). `UNDIVIDED_SHARE`
остаётся `None`. Коэффициенты малого просмотра никуда не переносятся:
gate проверяет ФОРМУ модели, а не масштаб на 4000/16000/64000.

## Предрегистрация

Этот раздел и пороги в коде закоммичены ДО замера.

Gate A убил `S + Σ cost(key)`. Код науки даёт три уровня работы на
период: группа (`generate_dyad`), пара (группа, δ) (`to_bins` и
префиксы), ключ (frontier и hull). Гипотеза для убийства:

```
T(G) = A + Σ_{δ ∈ D(G)} B_δ + Σ_{k ∈ G} C_δ(k),   C_δ одинакова внутри δ
```

Каждый уровень измеряется своим разбиением всех 72 ключей:

```
P1     неделёный                              групп 1, пар 4
P2     два целых блока в группе               групп 2, пар 4   A = C(P2) − C(P1)
P_dδ   делится ТОЛЬКО δ (×4)                  групп 2, пар 5   B_δ = C(P_dδ) − C(P2)
P4     блок на группу                         групп 4, пар 4   C_δ = (T_δ − A − B_δ)/18
F6     factorial (2h + x + 2d + t) mod 6      групп 6, пар 24  отложено
C6     cells (horizon, maximise)              групп 6, пар 24  отложено
```

Рука `r96.0:c1.25:R0:m1.0`. Просмотр подбирается удвоением от 2, пока
неделёный не стоит 3 с ЦП, затем пересчитывается на 18 с (полоса
10–20 с). Таймер — ЦП; стена и RSS пишутся рядом. Каждое разбиение
дважды, порядок ABBA (прямой, затем обратный), берётся среднее.

Kill-gates, по старшинству:

```
неполный прогон или бюджет 15 мин превышен      INCOMPLETE
любое изменение научного результата             KILL_SPLIT_CHANGED_SCIENCE
разброс повторов по любой группе > 2%           INCONCLUSIVE_NOISE
A, B_δ или 18·C_δ < −2·(наибольший разброс      KILL_NEGATIVE_COST
   сумм повторов)
то же, но в пределах шума                       INCONCLUSIVE_UNRESOLVED_COMPONENT
цена группы: C(P1) из P2 и P4, ошибка > 5%      KILL_GROUP_COST
factorial6 C или W, cells6 C, ошибка > 5%       KILL_HELDOUT
cells6 против factorial6 на части «только
   ключи» (накладные A + ΣB вычтены):
      > 10%                                     KILL_UNIFORM_WITHIN_BLOCK
      5–10%                                     UNRESOLVED — STOP
      ≤ 5%                                      PASS
```

При PASS статус оси внутри блока пишется как
`HORIZON_MAXIMISE_EFFECT_NOT_DETECTED_DAYS_UNMEASURED`: days в каждой
группе обоих зондов смешана поровну, и этот gate её не видит.

Добавления к рецензии, сделанные до замера: проверка согласия цены группы
(P2 против P4 — один лишний отсчёт, прежний аналог — согласие s_2 и s_4);
сумма cells6 как второй отложенный отсчёт (сумма от распределения внутри
блока не зависит); потолок шума 2% как предусловие; порядок ABBA.

Что даёт PASS: право СФОРМУЛИРОВАТЬ новый Gate B. Не даёт: подключить
модель, выставить `UNDIVIDED_SHARE`, посчитать 64000. При UNRESOLVED,
INCONCLUSIVE или любом KILL — STOP.

## Результат

Замер 10:07:32Z -> 10:13:48Z, **375.8 с из 900**, на предрегистрационном
коммите `8299599` при чистом дереве; наука совпадает с `7a62a39`; 4 ядра,
Python 3.11.15. Пробы: просмотр 2 / 4 / 8 -> 0.97 / 1.81 / 3.43 с ЦП,
выбран **просмотр 42**; неделёный 17.26 с ЦП — в полосе. Артефакт
`s5b-gate-a-f1.json`, sha256 `3f8b9b14…`; вердикт, пересчитанный из
записи, совпадает с записанным.

### Вердикт: INCONCLUSIVE_NOISE. STOP.

```

correctness                17 сравнений с базой, все identical
разброс повторов, группы   11.1%   потолок 2%   -> INCONCLUSIVE_NOISE
```

Потолок шума — моё добавление к рецензии, объявленное до замера. Вердикт
от него не зависит: следующая по старшинству проверка из списка
рецензии — отрицательные B в пределах шума — дала бы тот же
INCONCLUSIVE (все четыре B_δ отрицательны, от −0.02 до −0.36 с, при
границе шума −2.5 с).

### Разбор — постфактум, НЕ вердикт

**Почему дизайн не имел силы.** Каждое P_dδ добавляет ровно ОДНУ пару
(группа, δ). Если B порядка 2% неделёного (на 4000 было 1.97%), это
~0.3 с — а суммы одного разбиения между повторами расходятся до 1.25 с.
B здесь меряется разностью двух ~18-секундных сумм ниже порога шума.
По модели `F6 = P4 + 2A + 5·ΣB`: ошибка ΣB входит в предсказание с плечом
5. Чтобы объяснить все −34% (9.45 с), хватает ошибки ΣB в 1.9 с, то есть
около 0.5 с на каждую B при разбросе сумм до 1.25 с. Правдоподобно, но не
доказано; довода против модели здесь нет — и довода за неё тоже.

**Что устойчиво.** F6 и C6 стоят 1.61 и 1.58 неделёного при разнице
повторов 2.5% и 4.6%. Gate A на 4000 на раннере GitHub: cells6 — 1.576.
Штраф разбиений, перемешивающих блоки, воспроизвёлся на просмотре 42 на
другой машине. Одно отношение на двух просмотрах — это не проверка
линейности по просмотру.

**Согласованная, но непроверенная картина.** С A из P4 (0.79 с) средняя
B из F6 и C6 — 0.33 и 0.30 с (1.9% и 1.7% неделёного) против 1.97% на
4000. Ноль степеней свободы; проверкой это не является.

### Что сделало бы вопрос разрешимым

Предложение; без отдельного GO не исполняется, и пороги нового дизайна
объявляются до нового замера.

- **B с плечом, а не одной парой.** factorial6 против смежного
  `key_slices(6)`: групп поровну (A сокращается), пар 24 против 8, то
  есть разность равна 4·ΣB_δ.
- **Или прямой замер компонент.** Таймеры на `generate_dyad`, `to_bins`
  и поключевые функции в процессе замера, при проверке, что научный
  результат побайтно тот же, — A, B, C на вызов, а не разности шумных
  сумм.
- **Шум.** Группы не короче ~10 с (неделёный ~60 с вместо 18) и три
  повтора; потолок шума — на группах того размера, который решает.

## Чего этот gate НЕ сделал

Actions не запускались. Модель не подключена, коэффициенты никуда не
перенесены, `UNDIVIDED_SHARE = None`. Gate B не проектировался и
остаётся NO-GO; 64000 — NO-GO.
