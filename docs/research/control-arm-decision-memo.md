# §2.0.1 — Решение о контрольной руке

Статус: **K0 принят в принципе** (2026-09-18). Окончательная подпись под
H1/estimand/`δ` — **после** облегчения и заморозки `C`: изменение `C` меняет
причинный контраст, см. §6.1 и §8. Ни variance pilot, ни power design до этого
не двигаются.

## 0. Ограничение задачи, а не примечание

Instrumentation qualification §5 установила: **ни одна точка пути приёма не
пассивна.** Человек сам экспортирует чат каждый период, сообщает версию клиента,
фиксирует согласие, повторяет действие после каждого отказа приёма. Четыре
touchpoint'а из четырёх — осознанные действия.

Отсюда формулировка, с которой начинается всё остальное:

> В текущем протоколе контрольная рука **тоже** подвергается
> measurement/instrumentation exposure. Поэтому контраст не «воздействие против
> ничего»; это **пакет воздействия против пакета контроля**, и обе руки могут
> испытывать реактивность от самого участия в исследовании.

Это отсекает фантазию, ради которой стоит писать этот документ:

```
НЕТ:   Treatment = prompting        Control = естественное поведение
ДА:    Treatment = C + T            Control = C + K
```

Половину страницы можно было бы потратить на сравнение вариантов контроля,
которых фактически не существует.

## 1. Алгебра пакетов

Эксперимент оценивает `(C + T)` против `(C + K)`. Значит все три надо
перечислить поимённо, а не назвать.

### C — общее для всех рук

| компонент | периодичность | почему в C, а не в T |
|---|---|---|
| onboarding и согласие | разово | предшествует рандомизации |
| ручной экспорт чата и передача файла | **каждый период** | acquisition path; §5, крупнейший touchpoint |
| сообщение версии клиента и платформы | каждый период | `provenance.producer_version` — UNAVAILABLE из файла |
| повторное действие после отказа приёма | по событию | частота отказов = частота напоминаний о наблюдении |
| passive run-in до рандомизации | несколько дней | уже идёт под наблюдением |
| общий endline на 14-й день | разово | одинаков во всех руках по дизайну |
| осведомлённость «моё общение измеряют» | непрерывно | следствие всего перечисленного |

Последняя строка не риторическая. Она — причина, по которой `C` способен менять
поведение сам по себе, и именно её нельзя вычесть.

### T — только treatment

Calibration prompts: `END_OF_DAY` (≤1 кандидат в день) либо `DELAYED_EVENT`
(≤1 кандидат в день, привязанный к событию). `USER_INITIATED` в первом
эксперименте отключён полностью.

### K — только control

Предмет этого решения. Кандидаты — в §3.

## 2. Запрещённые слова

В этом документе и в prereg нельзя писать **passive control**, **no
intervention**, **usual behavior** — пока рядом буквально не перечислено, что
эта рука получает. Название руки ничего не доказывает. Контроль способен делать
больше работы, чем одинокий родитель на трёх сменах.

## 3. Кандидаты

```
K0  ничего сверх C
K1  attention-matched placebo: нейтральный контент, тот же ритм
K2  waitlist: C сейчас, воздействие после исследования
K3  sham-calibration: те же prompts, ответы не строят профиль
K4  product-realistic: работающие не-prompting функции приложения
K5  dose contrast: prompting реже (например, раз в неделю против ежедневного)
```

## 4. Матрица

| | **K0** ничего сверх C | **K1** нейтральный placebo | **K3** sham-calibration | **K5** сниженная доза |
|---|---|---|---|---|
| **что получает control** | только `C` | `C` + вопрос того же ритма, без отношения к паре | `C` + внешне те же prompts, ответы отбрасываются | `C` + prompting реже |
| **общее с treatment** | весь `C` | `C` + ритм прерываний | `C` + ритм + содержание + ожидание пользы | `C` + вид и содержание prompts |
| **causal contrast** | наличие prompting как такового | **содержание** prompting сверх факта прерывания | использование ответов сверх факта ответа | **доза** prompting |
| **reactivity contamination** | `C` активен в обеих руках | `C` + сам placebo вероятно меняет поведение | максимальная: prompt про отношения заставляет думать об отношениях | `C` + prompting в обеих руках |
| **expectancy / внимание** | участник видит, что prompts нет; асимметрия внимания максимальна | внимание уравнено, ожидание пользы — нет | уравнено почти полностью | уравнено, различается интенсивность |
| **ослепление** | участник — **нет**; исследователь и аналитик — да, и обязательно | участник — частично | участник — да, **ценой обмана** | участник — нет |
| **продуктовая реалистичность** | высокая: `C` и есть будущий продукт без prompting | низкая: нейтральные вопросы никто не отгрузит | нулевая: отгружать sham нельзя | высокая: доза — настоящий продуктовый рычаг |
| **этика / UX** | самая дешёвая; асимметрия внимания честно раскрыта | burden без пользы участнику | **deception**, требует отдельного обоснования | приемлемо |
| **H1 одной фразой** | «добавление prompting к нашему же measurement package меняет пассивно наблюдаемое поведение» | «содержание calibration-вопросов меняет поведение сверх эффекта самого прерывания» | «использование ответов меняет поведение сверх эффекта ответа» | «более частый prompting меняет поведение сильнее редкого» |
| **estimand** | эффект назначения `C+T` против `C` на `reentry_burden_H` и спутники | эффект назначения на **контент**, при уравненном ритме | эффект назначения на **использование ответов** | эффект назначения на **дозу** |
| **мощность** | контраст максимален | разбавлен | разбавлен сильнее всего | разбавлен, зависит от шага дозы |
| **что скажем при null** | «поверх уже активного measurement package добавление prompting эффекта не дало» — и **не** «prompting безвреден» | «дело не в содержании» | «дело не в использовании ответов» | «в этом диапазоне доза не решает» |

K2 (waitlist) и K4 (product-realistic) в таблицу не вошли намеренно. **K2** —
это K0 плюс обещание будущего доступа: ожидание меняет поведение в направлении,
которое мы не измеряем, а контраст остаётся тем же. **K4** в нашем случае
совпадает с K0: не-prompting функции приложения и есть `C`.

## 5. Два неприятных вопроса

### 5.1 Если контроль сам меняет поведение, какой эффект мы теряем?

```
только instrumentation        →  поведение уже меняется
instrumentation + prompting   →  поведение меняется несколько сильнее
```

Маленькая разница между руками тогда **не** означает «prompting безвреден». Она
может означать, что обе руки получили активный компонент и `C` уже съел часть
эффекта. Это делает H1 **консервативной**.

**Поправка к первой редакции.** Там стояло «положительный результат
интерпретируем, отрицательный нет». Слишком сильно — и это делает falsification
gate односторонним: угрозу подтвердить можно, а достаточно хорошо исключить
нельзя. Обычный `p > α` действительно почти ничего не говорит, но это свойство
плохо спроектированного null, а не null вообще. При заранее заданном практически
значимом `δ` и достаточно узком интервале:

```
оценка эффекта ≈ 0
95% CI целиком внутри [-δ, +δ]
```

утверждение становится содержательным: **при данном `C` данные исключают
incremental prompting effect той величины, которую мы заранее считали практически
значимой.** Это сильно не то же самое, что «ничего не нашли», и это ровно тот
ответ, ради которого gate и ставился. Иначе статистика опять получает роль
дверного звонка вместо измерительного прибора.

Чего такой null по-прежнему **не** говорит: насколько реактивен сам `C`. Руки
без `C` не существует, и этим дизайном вопрос не отвечается ни при каком раскладе.

### 5.1.1 Три исхода, а не два

Бинарный театр `p < .05 → меняет поведение` / `p > .05 → пожимаем плечами`
запрещён заранее. Исходов три, и они объявляются до данных:

| исход | условие | что значит для §0.1 |
|---|---|---|
| **REACTIVITY SIGNAL** | CI поддерживает эффект за пределами `δ` | посылка под угрозой, gate срабатывает |
| **PRACTICALLY NEGLIGIBLE** | CI целиком внутри `[-δ, +δ]` | incremental эффект такого размера исключён **при данном `C`** |
| **INCONCLUSIVE** | CI пересекает и область практической значимости, и окрестность нуля | точности не хватило; это **не** «нет эффекта» |

Отсюда прямое требование к следующему этапу: variance pilot и power design
отвечают **не** на вопрос «сколько людей нужно для значимости», а на вопрос

> сколько нужно, чтобы **различить** practically negligible effect и эффект,
> достаточный для слома продуктовой посылки.

`INCONCLUSIVE` обязан быть возможным результатом, а не признаком неудачи. Дизайн,
в котором он невозможен, врёт в одну из двух сторон.

### 5.2 Если эксперимент положительный, что именно мы отгружаем?

Если будущий продукт включает instrumentation, onboarding и prompting **вместе**,
то active control был бы разумным научным выбором: мы сравнивали бы то, что
реально различается между версиями продукта. Если же нужно доказать причинную
ценность **именно prompting**, контроль должен быть устроен иначе.

Наш случай: §0.1 — это **falsification gate на продуктовую посылку**, а не
проверка пользы. Посылка звучит как «можно пассивно измерять коммуникацию и
одновременно спрашивать о ней». Угроза посылке — **любой** prompting, а не его
содержание. Поэтому вопрос «что отгружаем» и вопрос «что сравниваем» здесь
совпадают, что бывает нечасто.

## 6. Рекомендация

**K0 как primary, при трёх условиях.** Выбор сделан по причинному вопросу, не по
мощности; то, что K0 даёт максимальный контраст, — следствие, а не основание.

1. **`C` перечислен и идентичен во всех руках**, и это проверяется
   инструментовкой, а не декларируется. Любой компонент, попавший только в одну
   руку, переводит его из `C` в `T` и меняет estimand.
2. **Null формулируется узко.** В prereg и в любом выводе: «поверх активного
   measurement package добавление prompting не дало обнаружимого эффекта».
   Формулировка «prompting не влияет на поведение» запрещена заранее.
3. **K1 предрегистрируется как follow-up**, а не придумывается потом. Если H1
   срабатывает, немедленно возникает вопрос «это прерывание или содержание»,
   и отвечать на него post hoc — значит выбирать ответ.

Ослепление: участника ослепить нельзя и притворяться не надо; **исследователь и
аналитик ослепляются обязательно**, распределение рук не видно на этапе расчёта.

### 6.1 Облегчение `C` — и почему оно ДОЛЖНО идти до подписи

`C` надо облегчить: в первую очередь заменить ручной экспорт автоматическим
локальным приёмом. Сейчас самый крупный touchpoint протокола — не prompt, а
еженедельное «выгрузи и пришли файл».

**Поправка ко второй формулировке первой редакции.** Там стояло «чем легче `C`,
тем меньше реактивности он съедает **до рандомизации**». Неверно: `C` на
рандомизации не заканчивается. Осведомлённость, приём и measurement exposure идут
**сквозь весь эксперимент**. Правильно:

> облегчение `C` уменьшает общий common-arm intervention и потенциальную
> реактивность **и run-in, и пострандомизационного периода**.

**И отсюда следует порядок работ, а не косметика.** Замена ручного экспорта
автоматическим приёмом меняет `C`, а значит меняет сам причинный контраст:

```
(C_old + T)  vs  C_old
        ↓
(C_new + T)  vs  C_new
```

Это **другой эксперимент**. Зафиксировать H1 и estimand на старом тяжёлом `C`, а
потом радостно улучшить acquisition — значит незаметно провести не тот
эксперимент, который подписывали. Поэтому подпись ставится **после** облегчения и
заморозки `C`.

## 7. Estimand, зафиксированный явно

```
Control:    C
Treatment:  C + prompting
```

> **ITT-эффект назначения на prompting, при общем measurement package `C`, на
> предрегистрированные исходы коммуникационного процесса.**

И то, что этим дизайном **не** оценивается — отдельным блоком, потому что именно
эти строки через полгода начнут тихо выпадать из пересказов:

```
НЕ оценивается:        эффект самого C
НЕ оценивается:        естественное поведение без участия в исследовании
НЕ идентифицируется:   эффект содержания prompt'а отдельно от
                       внимания, прерывания и ожидания пользы
```

Последняя строка и делает **K1 следующим экспериментом**, а не второй контрольной
рукой сейчас:

```
K0 сейчас:  добавляет ли prompting вообще?
K1 потом:   если да — это содержание или просто внимание и прерывание?
```

Отвечать на оба сразу означало бы раздувать дизайн раньше, чем первый причинный
эффект доказал право на существование.

## 8. Порядок работ

```
1  K0 принят как design choice IN PRINCIPLE            ✔
2  минимизация C: ручной экспорт → автоматический локальный приём;
   остальные необязательные touchpoint'ы убраны        ← здесь
   спецификация: c-target-spec.md (2A-2C заморожены)
3  instrumentation qualification ТОЛЬКО изменившегося участка —
   новый acquisition/user-flow. Extractor semantics не переоткрываются,
   154 мутанта заново не бьются из чувства религиозного долга
4  FREEZE C
5  окончательная фиксация: K0 · H1 · estimand · δ · формулировка null
6  variance pilot
7  power design: различить negligible и премиссо-ломающий эффект
```

Шаг 5 стоит после шага 4 не из аккуратности, а потому что шаг 2 меняет контраст.
